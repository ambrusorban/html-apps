Tropical Environment Art

A sequenced flowchart for taking a hand-built Gaea 2.2 terrain into a tropical Unreal 5.7 scene with PCG foliage, river systems and cinematic lighting — used as both a working guide and a project journal to ship with the final renders.

Software: Gaea 2.2 · Unreal Engine 5.7 · Pipeline: Heightfield → Landscape → PCG → Water → Light · Author: Ambrus Orbán

Project at a glance

Goal

Final render(s) of a believable tropical landscape — visible foliage variety, a flowing river, atmospheric lighting.

Key constraint

Foliage placement must respect terrain: no palms on cliffs, ferns near water, sand at river banks. PCG masks make this automatic.

Critical order

Build → Import → Water first (it carves the landscape) → then foliage → lighting last.

Deliverable

One or more cinematic stills / sequences plus this document, sharing the process and decisions.

Gaea 2.2 — Terrain & mask creation

All the procedural data Unreal will need is generated here. Get this right and the rest of the pipeline becomes plumbing.

Produce a tropical heightfield plus a full set of masks (slope, flow, soil, sediment, curvature, …) and export them as one synchronized package via the Unreal node.

HeightfieldErosionMasksTile-aware export
How to set up the project for exporting to Unreal? Q1.1
  1. New project · File → New. Pick the Terrain template.
  2. Project size (Properties panel): set the world size in km that you want in Unreal. e.g. 4 km × 4 km. This is the number you'll match in Unreal's landscape transform later.
  3. Viewport resolution: keep it low (1024) for fast iteration. Final resolution is set at build time.
  4. Build resolution: pick a value that maps cleanly to a recommended Unreal landscape size. Practical pairs: 1009, 2017, 4033, 8129. For a 4 km island, 4033 gives you ~1 m per quad.
  5. Tile the build (optional, for World Partition / open-world): in the Build panel set tile count, e.g. 2×2 or 4×4. Each tile then exports as a separate set of files Unreal can stream.
  6. File formats: Heightmap → R16 (16-bit raw) or 16-bit PNG. Masks → 8-bit PNG. Color → 8-bit PNG.
  7. Output folder: pick a clean dedicated path — the Unreal bridge will scan it.
Tip: Match Gaea's km size to Unreal's landscape XY scale up front. Re-scaling later breaks Z proportions and ruins erosion fidelity.
How does the Unreal export node work? Q1.2

The Unreal node lives in the Output category. It is the only node you should connect to when exporting for UE — it bundles every map together so the Gaea2Unreal bridge can pick them up as one package.

  • Multi-port: the node has dedicated input ports for Height, Color, and a stack of Mask inputs. You wire each Gaea output (your erosion's Wear output, a Slope node, a Flow output, a SoilMap, …) into a separate mask port.
  • Naming: rename each mask port (right-click) to something stable like Slope, Flow, Sediment. These names become the layer names in Unreal — keep them tidy now to save renaming material layers later.
  • Resolution: the node inherits the project's build resolution. Don't override per-node unless you know why.
  • Tiling: when the project is tiled, the Unreal node writes one folder per tile, with consistent naming the bridge uses to reconstruct the world.
  • Build: hit the build button in the toolbar (not the per-node preview). Only a real build writes the disk files the Unreal plugin needs.
Which maps should I export for use with PCG in Unreal? Q1.3

Export every mask the procedural foliage system might want to read. It's cheap to bake; expensive to redo.

Unreal Engine 5.7 — Project setup & landscape import

A clean project, the right plugins, and a scaled landscape before any artistry begins.

Stand up a UE 5.7 project, enable the plugins you'll use later, import the Gaea build with correct world dimensions, and verify the landscape scale matches Gaea before moving on.

UE 5.7PCGWaterGaea2UnrealWorld Partition
How to set up the Unreal project? Q2.1
  1. Engine version: install UE 5.7 from the Epic Launcher.
  2. New project: Games → Blank, Blueprint, no starter content (you don't want UE's default materials competing with yours), Quality: Maximum, Ray Tracing on.
  3. World type: for a single hero scene, an Open World template (UE 5.7 ships with one) is convenient — it pre-enables World Partition and a base setup. For tighter scenes, Blank is fine.
  4. Project Settings → Rendering: confirm Dynamic Global Illumination = Lumen, Reflection Method = Lumen, Shadow Map Method = Virtual Shadow Maps, Generate Mesh Distance Fields = on.
  5. Plugins to enable (Edit → Plugins, restart):
    • Water — rivers, lakes, ocean.
    • Procedural Content Generation Framework (PCG).
    • PCG Geometry Script.
    • Landmass (dependency of Water).
    • Gaea2Unreal Bridge — install via Fab/Epic Marketplace, then enable.
    • Optional: Volumetrics, Niagara for FX.
  6. Source control: at minimum, init a local Git LFS repo for /Content. Heightmaps and texture sets are large.
How to import the landscape from Gaea? Q2.2

Two routes — pick whichever your bridge plugin version supports best.

Route A — Gaea2Unreal bridge (preferred)

  1. In UE, open the bridge window (usually Window → Gaea Bridge or similar after enabling the plugin).
  2. Point it at the folder Gaea wrote on build.
  3. The bridge creates: a Landscape actor with correct quad/section/component layout, a LandscapeLayerInfo for each mask, and a starter material with mask-blended layers.
  4. Click into the landscape's Paint tab — your Gaea masks should appear as paintable layers, already filled.

Route B — Manual heightmap import

  1. Modes → Landscape → Manage tab → Import from File.
  2. Pick the heightmap (R16/PNG). UE auto-suggests Sections / Components — accept the closest Recommended entry whose total resolution matches your Gaea export.
  3. Set Location (0,0,0), Rotation (0,0,0), and the XY/Z scale (see Q2.4 below).
  4. For each mask: in the Paint tab, create a Layer Info, then import the corresponding PNG via the layer's Import from /File dropdown.
Gotcha: Importing tiled Gaea output manually is painful — the bridge handles the per-tile alignment for you. Use it for tiled / World Partition projects.
How does the Gaea2Unreal plugin work? Q2.3
  • It's a file-format-aware bridge: it reads the manifest Gaea writes next to the heightmaps/masks (resolution, world size in km, tile layout, mask names).
  • From that manifest it computes the right Unreal landscape parameters (component grid, scale) so 1 Gaea m → 1 Unreal m.
  • It registers the masks as LandscapeLayerInfoObjects in your /Content, so they're paint-stamped into the landscape and can be sampled by the material and by PCG.
  • It can be re-run: rebuild in Gaea, point the bridge at the same folder, and it will refresh height + masks without losing the foliage / water work you've done downstream.
  • It does not create rivers, foliage, or water automatically — those are still your job in UE.
How do size, cell size and scale relate to Gaea's size settings? Q2.4

Unreal landscape math, in plain terms:

  • Quad = the smallest grid square in the landscape mesh. 1 quad ≈ 1 m by default.
  • Section = a block of quads (7×7 or 15×15).
  • Component = 1 or 4 sections; the unit of streaming/culling.
  • Vertex resolution = (components × section quads) + 1. The "+1" is why recommended resolutions are 505, 1009, 2017, 4033, 8129 — each is N × 63 + 1.

Default scale in UE is 100 on every axis:

  • XY scale 100 → 1 quad = 100 cm = 1 m.
  • Z scale 100 → height range is ±256 m (total 512 m). Double Z to 200 → ±512 m.

Worked example matching Gaea:

  • Gaea project size: 4 km × 4 km, build resolution 4033.
  • Real metres per quad = 4000 / (4033 − 1) = ~0.992 m.
  • Set landscape XY scale = 0.992 × 100 = ~99.2 (or use 100 and accept a 0.8% rounding error).
  • If Gaea peaks are at 800 m elevation, set Z scale so range covers it: Z = 800 / 256 × 100 ≈ 312. Round up so erosion has headroom.
Sanity check: after import, drop a 1 m reference cube at sea level, then walk it up to a peak you remember in Gaea. If the peak is double-height or half-height, your Z scale is off.

PCG foliage — mask-driven biome layering

The system that places thousands of plants in seconds, using your Gaea masks as the rulebook.

Build a PCG graph that reads landscape layers and the photoscanned tropical pack to scatter ferns, palms, canopy trees and beach vegetation in the right places automatically.

PCG VolumeLandscape SamplerDensity FilterHISM
How to set up PCG for foliage? Q3.1
  1. Place a PCG Volume covering the area you want vegetated. Resize it to your island — bigger volumes work, but for iteration speed start with a small test region.
  2. Create a PCG Graph asset (right-click in Content Browser → PCG → Graph).
  3. Inside the graph:
    • Get Landscape Data → gives you the surface to scatter on.
    • Surface Sampler → emit candidate points across the landscape at a given density.
    • Get Landscape Layer Weight (one per mask: Slope, Flow, Soil…) → reads the painted layer at each point.
    • Density Filter → drops points whose density is below a threshold. Chain these to combine masks (e.g. Soil > 0.4 AND Slope < 0.3).
    • Transform Points → randomise rotation, scale; align to surface normal.
    • Static Mesh Spawner → spawn the actual plants as Hierarchical Instanced Static Meshes (HISM, default — good for performance).
  4. Assign the graph to the PCG Volume's Graph property, then hit Generate on the volume.
  5. Iterate: tweak thresholds, re-generate. Use the PCG Debug visualiser to see point density before spawning meshes — it's much faster.
I have a photoscanned tropical pack — how should the biomes layer? Q3.2

One PCG graph per biome, all sharing the same volume. Each graph filters on a different mask combo:

Biome / asset groupMask logicNotes
Beach palms, sea-grapeSediment > 0.5 · Elevation < 5 m · Slope < 0.2Cluster near shore. Add Z-jitter ±0.5 m so they read as wind-shaped.
Riverbank ferns, taroFlow > 0.3 · Soil > 0.3 · Slope < 0.4Use a Distance-from-River curve (cheaper alternative: a Flow distance falloff).
Canopy trees (large)Soil > 0.5 · Slope < 0.35 · Elevation 30–400 mLower density (~0.05/m²). Big rotation jitter, scale 0.8–1.4×.
Understorey ferns, palms (medium)Soil > 0.3 · Curvature < 0 (concave) · Wear > 0.2Fills valleys and gullies — that's where the moisture lives.
Cliff plants (sparse)Slope > 0.6 · Curvature < 0Tiny density. Keeps cliffs from looking bald.
Ground cover / debrisSoil > 0.2High density, small meshes. Cull at 30 m to save GPU.
Layer order matters: spawn canopy trees first, then have understorey filter out a radius around each tree (use Difference / Density Noise) so you don't get ferns clipping through trunks.
Which Gaea-baked maps are most useful here? Q3.3

In rough order of importance for tropical foliage:

  1. Slope — the single biggest gate; without it palms grow on cliffs.
  2. Flow — defines the riparian band (the most visually rewarding biome).
  3. Soil / SoilMap — separates "viable ground" from rock/sand.
  4. Sediment — beach and river-edge zones; lets you put palms specifically on sand.
  5. Curvature — bonus depth: concave = lush, convex = sparser.
  6. Wear / Wetness — moss, lichen, micro-debris.
  7. Elevation bands — coarse altitude biomes; you can also derive this in PCG from the height itself.

Skip Color for PCG — it's only for reference / material tinting.

Performance — how do I keep the editor responsive? Q3.4
  • HISM by default — Static Mesh Spawner already uses Hierarchical Instanced. Don't switch to actor instances unless you need per-plant logic.
  • Cull distance per species: ground-cover 30 m, ferns 80 m, palms 250 m, canopy trees 800 m+.
  • Generate per partition in World Partition setups — the volume only generates within the loaded cells, which is what you want.
  • Bake / cook PCG for the final shipped map (Generate, then Cook) so the engine isn't re-running the graph at runtime.
  • Nanite the trunk/branch meshes if the photoscan pack supports it; leaves usually need traditional LODs because of masked materials.

Water — rivers, creeks, ocean

Water bodies in UE are landscape-modifying actors. Place them before committing to foliage.

Lay down a river / creek system using the Water plugin, take advantage of Gaea's flow data as reference, then trigger any landscape-mask repaints before PCG runs.

Water pluginSplinesLandscape carvingSingle Layer Water
How does water work in Unreal? Q4.1
  • Water plugin ships with UE. After enabling it, the Place Actors → Water category gives you four bodies: River, Lake, Ocean, Custom.
  • Each body is a spline-driven actor. The spline points carry per-point parameters (river width, depth, velocity).
  • The plugin uses Landmass brushes under the hood: each water body emits a brush that modifies the landscape geometry beneath it (carves a riverbed, flattens a lakebed). This is non-destructive in the sense that disabling/deleting the actor reverts the change.
  • Rendering is Single Layer Water in the master material — translucency with a depth-based fade, refraction, caustics if you enable them.
  • Water Mesh Actor (added automatically with the first water body) is the global mesh that renders all bodies; don't delete it.
How to set up a river / creek? Q4.2
  1. Place Actors → Water → Water Body River into the level.
  2. Edit the spline: drag points to follow the natural valley you can see in your Gaea-imported terrain. Use the Gaea Flow mask as visual reference (paint it temporarily as a high-contrast landscape layer to see where water "wants to go").
  3. Per spline point, tune River Width (5–15 m for a creek, 20–60 m for a river) and Depth.
  4. Add Water Body Lake at any depression where the river pools (lagoons, deltas).
  5. Add Water Body Ocean if the scene has a coast — its spline defines the shoreline, and it tiles infinitely outward.
  6. Once you're happy with shapes, set the rivers' Landmass brushes to apply, and let the landscape rebuild.
Save before you carve: the first time a Water Body River is placed it can move 10 000s of landscape verts. Save the level just before, in case you want to revert.
Can I use Gaea's river maps directly? Q4.3

Not as splines — UE's Water plugin needs a hand-drawn spline; there is no direct importer for Gaea's vector river data. But Gaea's river / flow output is extremely useful in two indirect ways:

  • Visual guide: paint the Flow mask onto the landscape (as a paintable layer or a landscape material debug overlay). When you're dragging spline points, you can literally trace the bright pixels.
  • PCG input: even when the river is hand-placed, the Flow mask is still the cheapest way to drive riparian foliage density (Q3.2). The two systems coexist — UE renders the visible water, Gaea's mask drives the surrounding biology.

If your scene has many small creeks, consider skipping Water Body River for the smallest ones and relying purely on the Flow mask in PCG to scatter wet-zone vegetation — visually you may not need running water for a 50 cm creek.

Order of operations — water before foliage, or foliage before water? Q4.4

Water first. Always.

Reasoning:

  1. Water bodies modify the landscape geometry (riverbeds carve down, lakebeds flatten). If foliage is already placed, plants in the future riverbed will be either drowned or floating once the carve happens.
  2. Carving the landscape changes slope — and slope is one of the main inputs your PCG foliage depends on. Recompute foliage on the post-water landscape and the placement is consistent with what's actually there.
  3. Some scattered landscape-layer painting may need to be repainted after carving (e.g. you want a sand layer along the new riverbank). Doing this before PCG means the foliage sees the corrected layers.

Recommended sequence:

  1. Import landscape (Phase 2).
  2. Block out water bodies and let them carve.
  3. Paint corrective layers on the new banks (sand, mud).
  4. Generate PCG foliage (Phase 3).
  5. Polish lighting (Phase 5).
Iteration tip: water bodies can be temporarily hidden during PCG iteration (faster regenerate) and re-shown when reviewing the look.

Lighting & atmosphere

The Environmental Light Mixer wires up sun, sky, atmosphere and fog in one panel. Then it's tuning, not adding.

Build a believable tropical lighting setup using Lumen GI, Sky Atmosphere, volumetric fog and a tuned post-process volume — and identify the few settings that make or break the look.

Env. Light MixerLumenVSMVolumetric FogPost-Process
Where do I open the Environmental Light Mixer, and what does it do? Q5.1

Menu: Window → Env. Light Mixer. (UE 5.7 keeps it under Window; some legacy paths show it under Tools → Environment Light Mixer.)

The Mixer is a one-stop panel that creates and links the five core lighting actors of any outdoor scene:

  • Sky Atmosphere — physically based atmospheric scattering (the "sky" that the sun lights).
  • Sky Light — captures the atmosphere as ambient/indirect light. Set to Real Time Capture for outdoor scenes so it tracks sun changes.
  • Directional Light — the sun. Marked as Atmosphere Sun Light so the Sky Atmosphere uses its angle.
  • Volumetric Cloud — physically based clouds rendered into the atmosphere.
  • Exponential Height Fog — the workhorse fog actor; turn on Volumetric Fog on it for god rays / depth haze.

Click the small "+" beside each actor and the Mixer adds it to your level pre-wired. Once they exist, you can edit them either from the Mixer (compact) or in the Outliner / Details (full settings).

How does the Mixer work — and what's the right baseline for a tropical scene? Q5.2

The Mixer doesn't compute anything itself — it's a UI shortcut. The lighting is whatever the wired actors are doing. A solid tropical baseline:

  • Directional Light: Mobility = Movable; Intensity ~3.5 lux (for "sunny day"); a warm temperature (5500–6000 K); enable Atmosphere Sun Light; angle ~30–40° above horizon for a "tropical late afternoon" hero look.
  • Sky Atmosphere: defaults are very good. Bump Multi-Scattering to ~2.5 for the slight haze tropical air gives. Aerial Perspective is on by default.
  • Sky Light: Real Time Capture = on; Lower Hemisphere is Solid Color = off (so the ground reflects from below); Intensity Scale ~1.0. Recapture if you change atmosphere drastically.
  • Volumetric Cloud: keep the default m_VolumetricCloud_01; tune coverage in the material instance (~0.5 for partial cloud) — fully cloudy days kill contrast.
  • Exponential Height Fog: Volumetric Fog = on; Scattering Distribution ~0.7 (forward-scatter for godrays); Volumetric Fog Scattering Color slight warm tint; Density ~0.02–0.05 for jungle haze.
What are the most important things to look out for? Q5.3
  1. Lumen, not Lightmass. Confirm Project Settings → Rendering: GI = Lumen, Reflections = Lumen, Shadow Maps = Virtual. If you see "lighting needs to be rebuilt" warnings, you're on the old static path — switch to Lumen.
  2. Sky Light recapture: dynamic skylight is great, but on big scene changes (new water, big foliage) the capture can lag. Hit Recapture on the actor when the scene "looks washed".
  3. Auto-exposure trap: by default a Post-Process Volume's auto-exposure makes interiors look flat. Lock it down: place an infinite extent Post Process Volume, set Exposure to Manual with EV100 ~9 (outdoor sun), or Histogram with a tight min/max (e.g. 10–13).
  4. Directional Light shadows: enable Cast Cloud Shadows on the directional light if you have volumetric clouds — it sells the scale.
  5. Volumetric Fog quality: r.VolumetricFog.GridPixelSize down to 4 or 8 for crisper godrays in renders (slower in editor — turn back up for editing).
  6. Foliage and Lumen: masked materials with high translucency lose energy quickly. Consider a slight SubsurfaceColor on big leaf materials so they glow when backlit.
  7. Tonemapping: in the Post-Process Volume, color grade with warm shadows / cool highlights for the tropical wet-warm look. Bloom intensity 0.4–0.6, no more.
  8. Anti-aliasing: TSR (default in 5.7) is best for foliage; DLSS/FSR if available improves throughput at render time.
Render-time vs. editor: the editor viewport disables some volumetric quality and Lumen detail. Always evaluate the look through Movie Render Queue or a high-res screenshot at final settings before deciding it's wrong.
How do I take the final hero render? Q5.4
  1. Place a Cine Camera Actor. Pick a focal length 24–35 mm for landscape, 50–85 mm for hero details.
  2. Add the camera to a Level Sequence (even for a still — it gives you a consistent render pipeline).
  3. Open Movie Render Queue (Window → Cinematics).
  4. Settings preset: Path Tracer if you have time and want photographic realism; Deferred + Lumen for fast turn-around.
  5. Output: 16-bit EXR (multi-pass) for compositing; or PNG/JPG for direct shareable stills.
  6. Spatial / Temporal samples: 8 / 8 minimum for clean fog. 32 / 16 for a hero still on Path Tracer.
